iqm.qubit_selector.core.selector.score_layouts#

iqm.qubit_selector.core.selector.score_layouts(circuit, arch=None, metrics=None, *, client=None, readout_mode=ReadoutMode.NONE, remove_qubits_list=None, max_num_layouts=20000)#

Score every candidate layout for circuit, best first, with the error split by source.

Prefer this over select_layout() for deep circuits, where every candidate’s error rounds to 100% but total still tells them apart.

On a Star architecture the circuit’s MOVE gates are removed and the QPU is collapsed to qubit-qubit couplings, so metrics must hold the matching fictional CZ fidelities, as get_metrics_data() returns them.

Give the QPU either as client, from which the architecture and metrics are fetched on every call, or as arch and metrics without a client.

Parameters:

  • circuit (Circuit) – The circuit to place.

  • arch (DynamicQuantumArchitecture | None) – Architecture of the target QPU. Leave out when client is given.

  • metrics (MetricsData | None) – QPU metrics used for scoring. Leave out when client is given.

  • client (IQMClient | None) – Client to fetch the architecture and metrics from.

  • readout_mode (ReadoutMode) – Which readout metric to include, if any.

  • remove_qubits_list (list[str] | None) – Physical qubits to keep out of every layout, e.g. known-bad ones.

  • max_num_layouts (int) – Maximum number of candidate layouts to score. On a sparse coupling graph it is also the VF2 state limit of each search; see VF2Enumerator for how to size it.

Returns:

All scored layouts, lowest total first.

Raises:

  • ValueError – If the QPU is not given as either client alone, or arch and metrics without a client.

  • ValueError – If the circuit acts on more qubits than the QPU has left after remove_qubits_list.

Return type:

list[LayoutScore]
