IterationTracker#

Module: iqm.iqm_client.iqm_client

class iqm.iqm_client.iqm_client.IterationTracker(client: IQMClient, iteration_data: IterationData)#

Bases: object

Context and lifecycle manager for an iteration on IQM Server.

An iteration is an exclusive timeslot for a particular quantum computer on IQM Server, during which only the jobs the iteration owner submits to the iteration-specific job queue are being executed on that quantum computer. Hence it e.g. enables workflows based on quick quantum-classical iteration, such as various quantum optimization algorithms. Unlike the normal timeslots which are reserved in advance and take place during a fixed time interval, iterations can be requested on demand, and can be ended at any time.

  • A new iteration is requested using IQMClient.request_iteration(), which returns an instance of this class if successful. The request goes into the normal server job queue, and once it reaches the front of the queue the iteration becomes active.

  • An existing iteration can be queried using IQMClient.get_iteration().

The user is billed for the entire time from when the iteration becomes active, until either the iteration or the last executed job in the iteration ends, whichever comes last. This means that keeping the iteration active costs, whether jobs are executing in it or not, since it reserves the quantum computer for your exclusive use.

The user can end the iteration anytime (even before it has become active) using end(). This will also cancel the jobs submitted into the iteration that have not started executing yet. The same happens if the iteration ends on its own when it reaches its maximum duration. The currently executing job(s) are allowed to finish. IterationTracker can be used as a context manager, in which case it ends the iteration automatically when you exit the context.

For the exact description on how the iteration workflow and billing works, see the IQM Server API documentation on IQM Resonance.

update() → IterationStatus#

Refresh iteration_data by querying the server, unless the status is already terminal.

Once the iteration reaches a terminal status (see IterationStatus.terminal_statuses()), iteration_data no longer changes, so this method skips the server query and returns the cached status instead.

Returns:

Current status of the iteration (included in the refreshed iteration data).

Return type:

IterationStatus

wait_until_active(*, timeout_secs: float = 10800.0, polling_interval: float = 1.0) → IterationStatus#

Poll the server for the iteration status until it is no longer WAITING, or until we hit a timeout.

The iteration stops waiting either by becoming IterationStatus.ACTIVE, or by reaching a terminal status (see IterationStatus.terminal_statuses()) without ever becoming active, e.g. if it is ended before its turn comes up.

Will stop the polling (but does not end the iteration) upon receiving a KeyboardInterrupt (Ctrl-C). If you want to end the iteration, call end().

Updates iteration_data.

Parameters:

  • timeout_secs (float) – Maximum time to wait (in seconds). If nonzero, the method will return the last polled status after this period even if it is still IterationStatus.WAITING.

  • polling_interval (float) – Time to wait (in seconds) between successive polling requests.

Returns:

Last seen iteration status. Not necessarily IterationStatus.ACTIVE, see above.

Raises:

KeyboardInterrupt – Received Ctrl-C while waiting for the iteration to become active.

Return type:

IterationStatus
