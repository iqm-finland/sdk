Version 9.0.0 (2025-06-13)#

Features#

  • Reintroduce StationControlInterface and make both StationControlClient and IQMServerClient inherit it to implement the same interface.

  • Add new methods to StationControlInterface, implemented by StationControlClient. IQMServerClient doesn’t implement these new methods yet, but raises NotImplementedError instead. :issue:`SW-1078`

    • get_default_calibration_set()

    • get_default_calibration_set_observations()

    • get_dynamic_quantum_architecture()

    • get_default_dynamic_quantum_architecture()

    • get_static_quantum_architecture()

  • Support also string UUIDs in StationControlClient methods, instead of only UUID objects. This always worked in practice, since UUIDs were instantly serialized to strings anyway. However, it gave type warnings for the users when string given. No functional changes, but no more type warnings.

Breaking changes#

  • Remove StationControlClient.init(), StationControlClient.get_calibration_set_values() and StationControlClient.get_latest_calibration_set_id() methods. Those aren’t REST API related and needed only by Pulla for now, and they don’t belong to StationControlInterface since there is already StationControlInterface.query_observation_sets(), StationControlInterface.get_observation_set() and StationControlInterface.get_observation_set_observations() which can be used for the same purpose. IQMServerClient still has the original methods and it should be later refactored to implement the same interface as StationControlClient.

Features#

  • Add optional wait_task_completion boolean parameter (default True) to station control client’s run().
